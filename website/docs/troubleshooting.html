Troubleshooting

The status footer (bottom-left of the app) is the diagnostic hub — it shows recording state, pending screenshots, and the last error.

No timeline cards are appearing

  1. Is a provider configured? A red warning in the status footer means no — set one up in Settings and use Save & test connection.
  2. Are screenshots pending? The footer counts shots awaiting analysis. Batches run every ~15 minutes; click Analyze now to force one.
  3. Is there an analysis error? The footer shows the provider's last error (bad key, quota, model without vision support). Fix, then Analyze now — failed batches retry automatically after 5 minutes.

The dot says it isn't recording

Provider errors

  • 401 / invalid key — re-paste the key; check for stray spaces.
  • 429 / quota — free-tier limits hit; batches retry with backoff, or switch model/provider.
  • Ollama: connection refused — is ollama serve running? Is the model pulled (ollama pull qwen2.5vl)?
  • Model has no vision — timeline analysis needs a vision-capable model; see providers.

Timeline quality is poor

  • Try a stronger model (e.g. Claude, or a larger local model).
  • Shorter batches (Settings → "Analyze batches of") produce finer-grained cards.
  • Multi-monitor users: enable Capture all displays so activity on secondary screens is seen.

Disk usage

Screenshots are ~100–200 KB each — roughly 0.5–1 GB per week at defaults, self-cleaning after 7 days. Lower the capture frequency or retention in Settings if that's too much.

Start over

  1. Quit DearDiary from the tray.
  2. Delete %APPDATA%\DearDiary (this erases your journal too — back up deardiary.db first if you want history).
  3. Relaunch; the setup wizard runs again.

Still stuck?

Email support@deardiary.app or open a GitHub issue with what the status footer shows.
